# Как работать в Ekstasis

Короткая памятка для автора — Александра Майи.

## Начало работы

Откройте OpenCode из каталога:

```text
/home/rudra/Projects/Ekstasis
```

При открытии проекта по умолчанию поднимается `curator` — куратор и единственная
точка входа автора. Пишите ему обычными словами, что нужно сделать. Команды ниже
— короткие ярлыки для частых ритуалов, а не обязательный синтаксис.

Автор говорит только с куратором. Чтеца, критика, корректора и картографа напрямую
не вызывают: куратор сам решает, кого позвать, когда вы формулируете задачу или
используете команду.

## Команды

| Команда | Ритуал | Кого зовёт куратор | Куда попадает результат |
|---|---|---|---|
| `/reading <часть>` | чтение | чтеца | датированный отчёт в `Отзывы/` |
| `/critique <часть>` | критика | критика | датированный отчёт в `Отзывы/` |
| `/corrections <часть>` | правки | корректора | отдельный датированный файл в `Тетрадь правок/` |
| `/apply <файл тетради>` | применить | куратор готовит применение отмеченного | сначала точный diff и запрос подтверждения; рукопись не меняется автоматически |
| `/flow` | поток | куратор проверяет состояние проекта | состояние частей, чтений и связей в ответе куратора |
| `/map [часть]` | карта | картографа | `Картотека/Вселенная/`; без аргумента — полный проход по корпусу |

У селектора должна быть однозначная часть, файл или фрагмент. Если аргумент
`/map` пуст, картограф проходит весь корпус. Условная нумерация глав не задаёт
хронологию.

Чтец и критик сами записывают полный отчёт сразу в назначенный файл `Отзывы/`.
Куратор получает только путь и короткий абстракт: он не пересказывает, не
сокращает и не перезаписывает отчёт.

## Кто есть кто

**Чтец.** Работает в два этапа, и порядок нерушим: сначала чистое переживание —
что случилось при чтении, где ударило, где сбилось дыхание; затем механизм
метафоры. Наивное первое чтение не смешивается с разбором.

**Критик.** Показывает место текста в поле традиции и хранит канон Абстрагизма.
Говорит честно — без комплиментов и без разноса. Его наблюдения никогда не
становятся правками.

**Корректор.** Проверяет только норму языка и вызывается только явно, через
`/corrections` (правки). В тетради три класса пунктов: `норма`, `сомнение`, `возможно
намеренное`. Последний — вопрос автору, а не предложение исправить.

**Картограф.** Вскрывает вселенную, но не создаёт её. Ведёт регистры: голос,
локусы, сущности, законы, связи, нить, натяжения и время. Каждая запись опирается
на цитату, файл и номер строки. Внутри записей есть разделы `Сказано`, `Выведено`
и `Спрошено`.

Все части — области одной метавселенной, а не отдельные произведения. Тексты —
пазлы одной мозаики, через них проходит красная нить. Время написания и внутреннее
время мира ведутся раздельно.

## Как проходят правки

Это единственный режим, в котором вообще может обсуждаться изменение рукописи.

1. Запустите `/corrections <часть>` (правки). Корректор создаст датированный файл в
   `Тетрадь правок/`. Каждый пункт имеет строгий формат:
   `- [ ] **1.** тип: норма`, затем вложенные однострочные поля `файл`, `строка`,
   `цитата`, `предложение`, `причина` именно в этом порядке.
2. Откройте файл в Obsidian. Поставьте `[x]` только там, где согласны с пунктом.
   Меняется только пробел внутри скобок: `[ ]` → `[x]`. Можно отметить часть
   пунктов или не отметить ни одного.
3. Запустите `/apply <файл тетради>` (применить). Куратор прочитает только указанный
   файл детерминированным парсером `corrections.mjs`, отберёт исключительно
   `[x]`, подготовит точный diff и покажет его вам.
4. До отдельного явного подтверждения ничего не записывается. Даже после
   подтверждения применяется только буквально согласованный diff; для записи в
   рукопись координатор должен отдельно открыть ровно этот scope.

`[ ]`, неоднозначная отметка и молчание означают отказ. Неотмеченное не
применяется никогда. Ни один агент не может сам тронуть рукопись: зона
`В поисках Пустоты/` закрыта на запись на уровне permissions, а не договорённости.

## Что агенты не сделают никогда

- не правят текст без отметки и отдельного подтверждения;
- не «улучшают» стиль, не выравнивают ритм и не сокращают;
- не чинят намеренный слом нормы;
- не психоанализируют автора и не делают биографических выводов;
- не разбирают часть как отдельное произведение;
- не выстраивают хронологию там, где текст её не утверждает;
- не запирают будущие тексты в уже нарисованную карту.

## Куда что кладётся

```text
В поисках Пустоты/  — рукопись; закрыта на запись
Отзывы/             — чтение и критика
Тетрадь правок/     — предложения корректора с чекбоксами
Картотека/          — картотека проекта
Картотека/Вселенная/— карта внутреннего мира
Канон/              — канон и поэтика проекта
Память/             — состояние и память работы
```

## Первые шаги

1. Начните с `/reading В поисках Пустоты/В поисках Нетленного.md` (чтение): это проверка,
   попадает ли оптика чтеца в автора вообще.
2. Затем запустите `/map` (карта) — полный проход по трём частям.
3. К `/corrections` (правки) и корректору переходите, когда захочется порядка в рукописи, не
   раньше.

Если чтец окажется глухим, всё остальное не имеет смысла. Это стоит узнать на
первом тексте.

## Мелочи, о которых стоит знать

- Команды набираются латиницей: OpenCode берёт имя команды из имени файла. Русские
  названия — имена ритуалов, а не синтаксис; можно просто попросить куратора по-русски
  («прочитай мне такую-то часть») — команда лишь ярлык и не обязательна.
- После изменения агентов или команд перезапустите сессию OpenCode: иначе новые
  настройки не подхватятся.
- Проект публичный на GitHub: <https://github.com/atmavichara108/Ekstasis>.
  Рукописи видны в сети.
- Чтец, критик и картограф работают на дорогой модели (opus). Это осознанный
  выбор: качество чтения здесь и есть продукт. Корректор работает на дешёвой
  модели и может давать ложные срабатывания в пунктуации; тогда его модель
  поднимут.
- Чат с куратором — не единственная память. Состояние живёт в `Память/` и
  регистрах, поэтому работу можно бросить и вернуться к ней позже.
